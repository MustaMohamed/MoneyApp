# Returns and reads (every /ship dispatch, and the conductor's own reads)

**Goal:** no whole diff, check run, comment thread or report enters the conductor's context unless a verdict calls for it. The return shape and the open list bind every /ship charter, a lens or charter added later included.

**Return.** A /ship dispatch returns at most 15 lines, in this order: the verdict line, in its charter's words, ending `build: REBUILD <the files mqa up listed>` when the dispatch met it; the counts line, `calls <n> · sha <sha> · files <k>`, `<k>` the repository files it changed, 0 for a read-only dispatch; where the review worktree line of [SKILL.md](../SKILL.md) → Worktrees asks for them, `worktree: <the path Bash ran in>` and `LSP: used | not used, <why>`; on the quality lens, one line per danger surface with its Flag or `none`; on the implementer, `chain: <the chain log path>`, then on a `Verify emulator` ticket its `screens:` and `invariants:` lines ([implement.md](implement.md) → Charter); last, `report: <absolute path>`, followed by ` · <section> <first>-<last>` for each report section a verdict of the open list sends the conductor to. Nothing else.

**Report.** Everything else is in the report, at the path the dispatch names, `~/.ship/MoneyApp/MA-XXX/findings/<role>-<sha>[-<k>].md`. `<role>` is one of `test-writer`, `implementer`, `correctness`, `quality`, `conformance`, `render`, `verifier`, `recheck`; `<sha>` is the 7-character head the dispatch starts from, a continued fix cycle's SendMessage included; `-<k>` numbers any parallel dispatches of one role on one head, the file-disjoint fixers of [triage.md](triage.md) item 8 and the per-fix re-checkers of [recheck.md](recheck.md) item 3 alike. Each section is one `## ` heading. For a read-only dispatch the report is the one file it writes, the render lens's walk and screenshots under `findings/render/` aside, and it is never in a worktree. A re-dispatch on the same head overwrites a report the conductor has already read.

**Open list.** The conductor opens a report only on these verdicts: `findings` (a lens, or a re-checker with new delta findings), `not-fixed` (the re-checker), `partial` and `refuted` (the verifier), `over budget`, `build held`, `blocked`, `discrepancy`, `deviations` and an `invariants:` line that names a node, at its `invariants` range (the implementer; an `invariants: holds` line, with or without ` · unread <k>`, opens nothing), `failing` (the `after` test writer). It reads the range the `report:` line names, with Read `offset` and `limit`, never the whole file; a range that does not start on its section's heading is found again with `grep -n '^## ' <report>`. A report the next dispatch consumes goes to it by path, and the conductor does not open it: the test writer's to the implementer, the implementer's to the `after` test writer. The implementer returns the path of its chain log, `findings/chain-<sha>.log`.

**Not bound.** The restatement check of a parked record ([SKILL.md](../SKILL.md) → Parking step 2) gets the record text alone, and its restatement is read whole. The built-in `code-review` is a Skill call, not a dispatch, and its return is read as it comes. The three paragraphs above bind neither.

**Shell reads.** The conductor reads PR checks as `gh pr checks <pr-url> --json name,state --jq '.[] | [.name, .state] | join(" ")'`. At triage it reads the diff's stat and the Non-goals hunk headers of [triage.md](triage.md) item 1, and no step reads the full diff. Setup reads the issue's comments as their first lines. A change after the summary is read per [merge.md](merge.md) → A change after the summary. Every other result ends `2>&1 | tail -20` or `| grep <pattern> | head -20`. A command whose exit code gates the next step writes to a log under `~/.ship/MoneyApp/MA-XXX/` named for its step, and the conductor reads the log's tail: `<command> > <log> 2>&1; echo "exit $?"; tail -20 <log>`, and for a chain `A > <log> 2>&1 && B >> <log> 2>&1; echo "exit $?"; tail -20 <log>`. No command here uses a brace group, a subshell, `git -C` inside a worktree session or `\(` interpolation in jq: the worktree guard refuses all four.
