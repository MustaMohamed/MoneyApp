# Issue review

The review step of the define workflow, and the only road to Ready For Development: an issue that passes gets `Reviewed <date>` on its header line, a split parent as much as a leaf, and `board.sh promote` moves a marked leaf under a marked parent once every Depends on is closed. The review ends with every `ask` answered and written into the body, then marks and promotes in the same run; Ready For Development means nothing is open and the ticket is counted within the size gate. An unattended run never waits on the user: it parks each `ask` as a question record, [references/question-record.md](references/question-record.md), and `/queue asks` puts it to the user later. Ready For Development is one-way: a leaf there is never reviewed or moved back here, and only a record answer at step 7 edits it. Runs after `/boundaries` locks an epic or a task, after `/tickets` creates its children, and again whenever a Defined issue should be checked. Every lens runs in a fresh subagent that did not write the bodies and is read-only on the repository, so the skill works in the session that drafted them. The run stops for the user only on an `ask` or an open record. Its one write is the lease, outside the checkout, one per issue under review ([queue § Lease](../queue/SKILL.md)); an unattended run works in the primary checkout and writes nothing to it. The `unslop` skill binds every delta.

## Preconditions

`bash scripts/board.sh get <n>` says Defined, or Ready For Development or In Progress on a parent with sub-issues, since a parent mirrors its furthest child. A leaf at Ready For Development is refused: reply `Next: /prep <n>` and stop. Anything else: say what you found and stop.

## What gets reviewed

The issue's children when it has any, otherwise the issue itself. Among the children, only those whose board Status is Defined or Todo (a task created for its own breakdown): a child at Ready For Development or past it is listed as skipped, and only a record answer at step 7 edits it.

```bash
gh api repos/MustaMohamed/MoneyApp/issues/<n>/sub_issues --paginate --jq '.[] | select(.state == "open") | .number'
gh api repos/MustaMohamed/MoneyApp/issues/<n>/parent --jq .number   # exit 1, with the error JSON on stdout, when it has none
node scripts/board_next.mjs --format json </dev/null | jq -r '.actions[] | "\(.number) \(.status)"'   # one read for every open ticket; gh project item-list needs read:org
```

## Lenses

Self and Parent go to group reviewers under [references/reviewer-charter.md](references/reviewer-charter.md); Children goes to one set reviewer under [references/children-lens.md](references/children-lens.md).

- **Self**, every issue: complete against its own Goal and the code, outcomes not solutions, Rules and Acceptance assertable, shape, triggers, overlap with sibling epics; on a ticket, the state walk, the copy check and the `Screen checks` rows.
- **Parent**, any issue with a parent: the parent's Rules carried, a Building bullet served, the size gate counted against the real files, Verify and Flags true to the code, Depends on real.
- **Children**, a set: coverage both ways for Building and for Rules, edges across the set, overlap on the milestone, the cut.

An epic gets Self, then Children once its tickets exist. A leaf ticket gets Self and Parent. A task cut further gets all three over its life, one hop at a time, and its own Self and Parent again in every round over its children while its header reads `Reviewed none`: a parent is marked before its children are. Each review checks a body against its own parent only; the parent was checked against its parent when it was the child.

## Steps

1. **Gather.** The bodies under review and their board Status; the open records on `<n>` and on each issue under review, `bash scripts/board.sh questions <issue>`, each with its body, `gh api repos/MustaMohamed/MoneyApp/issues/comments/<id> --jq .body`; the parent body when there is one; the milestone sheet: every issue on the milestone with number, title, labels, state, the first line of its body and its `## Decisions` lines, `gh issue list --milestone "<m>" --state all --limit 1000 --json number,title,labels,state,body`; when reviewing children, the cut, `gh issue view <parent> --json comments --jq '[.comments[].body | select(startswith("Cut:"))] | last'`. Before the first dispatch, run the Entry check of [queue § Lease](../queue/SKILL.md) for every issue under review, `<n>` and each child it reviews, then write one lease per issue, `skill=issue-review` and `worktree=` the primary checkout. A run `/queue Defined` started on a parent finds the parent's lease written, its own by the `task=` line, and writes each child's with that same `task=` line.
2. **Map the code.** Reviewing children: one read-only scout (`subagent_type: Explore`, breadth "medium") lists, per child, the folders, screens, migrations, money paths, native config and user copy it touches, and names its main surface, the deepest folder under `src/modules/` it changes; a child with no code surface (a design ticket) is its own surface. Reviewing one issue: no scout; the reviewer maps for itself.

   **Size every leaf the way its planner will.** One fresh sizer per leaf under review (`subagent_type: general-purpose`), all in one message, in the same message as the scout: [references/sizing-charter.md](references/sizing-charter.md) verbatim, the leaf's body, the parent body, and the absolute path of a checkout with a real `node_modules`, since the count runs on LSP find-references. A parent, an epic and a body at Todo get no sizer. The sizer's list is the count: it goes to the group reviewer beside the body, and step 8 writes it as the body's `Size:` line.
3. **Group.** Children that share a main surface form a group, in MA order, at most four per group; the fifth starts the next group. A child on two surfaces goes with its main one. A single issue is its own group. A split parent whose header reads `Reviewed none` is its own group in the same round, reviewed against its own parent.
4. **Dispatch** one fresh subagent per group, all in one message (`subagent_type: general-purpose`): the charter verbatim; the group's bodies, each with number, title and board Status; the parent body; the code map; each leaf's sizer return; the milestone sheet; the paths of the standard the bodies follow ([epic-body.md](../epic/references/epic-body.md) or [ticket-body.md](../tickets/references/ticket-body.md)), of CLAUDE.md, of `.claude/skills/emulator-verify/features/`, of the canvas folder `~/.ship/MoneyApp/canvas/` and of `docs/adr/`, which the reviewer reads itself before it asks anything. Reviewers return deltas as text; they run no `gh` and edit no file.
5. **Children lens**, when reviewing a set: one more fresh subagent (`subagent_type: general-purpose`) with [references/children-lens.md](references/children-lens.md) verbatim, every body under review, the parent body, the code map, the milestone sheet and the cut. Dispatched in the same message as the groups.
6. **Stop.** A typed run: show every mechanical delta grouped by issue with its replacement text; step 7 applies them with no question. Then put each open record from step 1 to the user, then every `ask`, one question at a time, the answer the evidence points to first; an `ask` whose `Prior art:` line names a source that answers it, or whose answer the conductor finds in the sources the "Before an `ask`" paragraph of [reviewer-charter.md](references/reviewer-charter.md) lists, is not asked: it is applied as a mechanical delta with that source cited, and the reply names it under the issue; each with its visual per [question-visuals.md](references/question-visuals.md); an `ask` on a question an open record holds is not asked, the record is. A record holds an `ask` when it sits on the `ask`'s issue, its `Asked by:` line names the same check id and its `Blocks:` line names the same line; any other `ask`, a second from the same check on the same issue included, is asked or parked on its own. Each answer becomes a delta on the body it lands on, a chosen cut becomes a `Cut:` comment at step 7, and an answer that names a new task is written as a Rules line naming the new task, for `/tickets` to cut afterwards. A clean review shows `approve` per issue and asks only the open records; a run with no open record and no `ask` has no stop. A typed run parks nothing: a question the user defers ends the run once step 7 has applied the mechanical deltas, nothing is marked, a deferred record stays open, and the reply says which issue waits on what. An unattended run asks nothing: each `ask` becomes a record per [question-record.md](references/question-record.md) on the issue it lands on, posted with `gh issue comment <n> --body "$RECORD"` once its restatement check is done; an `ask` on a question an open record holds is not parked again. The run then applies, marks and replies as below, and ends.
7. **Apply.** In every run, per issue with deltas, take the body fetched in step 1, apply every mechanical delta first and then every answer, `gh issue edit <n> --body "$BODY"`. Each answer is written per [ticket-body.md § Writing an answer](../tickets/references/ticket-body.md#writing-an-answer), its Decisions line naming the step `/issue-review`. An answer whose `into:` is `#<n> Cut` edits no body. A typed run posts the chosen cut's `writes:` text once with `gh issue comment <n> --body "Cut: <text>"`, the comment the next run's step 1 reads. An unattended run posts no cut; [asks.md](../queue/references/asks.md) step 4 posts it once the user chooses. Each open record answered at step 6 is written as that step 4 writes an answer, on an `into:` sibling whatever its column, the record closed per [question-record.md](references/question-record.md) § State; its body bullets go in the one edit above and its cut is the one comment above. The lock line and the title stay. An epic body is edited here only while it has no tickets; once they exist a correction is a comment on the epic plus a Rules edit on the owning ticket. A split parent's body is edited like a leaf's, as the union its children serve; a delta on a parent line lands on the child that owns it in the same round.
8. **Mark and promote.** An issue passes when every `ask` on it was answered at step 6 and its sizer returned `within`. In both run kinds the sizer's `Size:` line replaces the body's on every leaf it counted, whether or not the leaf passes. No issue whose `bash scripts/board.sh questions <n>` prints a line gets a `Reviewed` date; a date already on its header stays. An unattended run that parked an `ask` leaves its issue in the column it sat in. A leaf counted over the gate, or at it, is never marked, whatever the answer to its size `ask`: the seam goes into its body, it stays at Defined with `Reviewed none`, and the reply says `Next: /tickets <n>`; its children are reviewed in the next run. A run the user ended on a deferred question marks nothing. A deferred open record moves nothing. In a typed run, each issue with an `ask` from this run left unanswered, deferred or never reached, reads `Reviewed none` at Defined wherever it sat, `bash scripts/board.sh status <n> Defined`. Per passing issue under review, split parent or leaf: write `Reviewed <today>` on its header line, `gh issue edit <n> --body "$BODY"`; a leaf under a parent that reads `Reviewed none` is not marked, its parent passes first. Then once, `bash scripts/board.sh promote <n>`, which moves every marked leaf with every Depends on closed and a `Size:` line within the gate to Ready For Development, and names each one it refuses: the children when `<n>` has any, `<n>` itself otherwise. A parent, epic or split task, is never pulled; promote lifts it to Ready For Development with its first child, as its column mirrors its children. Nothing is created or closed.
9. **Reply.** Per issue, `approve` or `<k> deltas applied`, with its board Status after step 8 and the children skipped as in delivery; one line with the number of dispatches and minutes; then `Next: /tickets <n>` after an epic's Self review and for each leaf counted over the gate, `Next: /prep <n>` for each leaf now at Ready For Development, or `Next: /queue asks` for each issue with a parked record. Remove every lease this run wrote, here and at every other exit.
