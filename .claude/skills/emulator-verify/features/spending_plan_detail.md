# Spending plan detail

Route `/budget/plans/[id]`. Screen `src/modules/budget/screens/budget/spending_plan_detail/index.tsx`, Flexible card `spending_plan_detail/components/spending_plan_detail_flexible_card.tsx`. Frame D2 (budget canvas) draws the header, the load states and the Edit foot (MA-324), the Category limits card (MA-326), the active hero (MA-331) and the Flexible card (MA-327); frames S18, S19 and S29 draw the upcoming and ended heroes (MA-327). Every plan mounts the hero (`id="spending-plan-detail-hero"`, the shared `DetailHero`); the summary card is gone. This file carries only the states tickets have reached — add the rest when a ticket reaches them.

## Reach it

- User path: the `Budget` tab, the `Plans` lens (`Strings.budgetPlansTab`), then a plan card.
- Script: `id=$($MQA db "select id from spending_plans where name='<n>'" | sed -n 's/.*"id": "\(.*\)".*/\1/p')` then `mqa open /budget/plans/$id`. Use it for every plan after the first: the list route reaches only the cards on screen (§ Gotchas).

## Gotchas

- The ended hero's `Within limit` tag is local to plan detail; the Plans card on `budget.md` keeps its `On track` chip for the same plan (MA-306 owns that row).
- The Flexible footer is a `FactRow` inside `DetailRowsCard`; it carries no divider of its own, so the hairline above it comes from the card and shows only when rows precede it.
- Back restores the `Plans` list to its previous scroll offset, so a scroll-and-find loop re-reads the cards it already visited and never brings the off-screen ones up; walking all four statuses costs a deep link per plan, not a second visit to the list (MA-087 render lens reached 2 of 4 this way).
