### 1. One shared local-day source that sheets read as a value
- File: `src/utils/use_local_today.hook.ts` (new)
- Change: export `useLocalToday`, two overloads, arguments in order: `(seed: string, isActive: boolean): string` and `(seed: string | undefined, isActive: boolean): string | undefined`. `seed` is required and is the local `YYYY-MM-DD` the caller reads today (not null; `undefined` only on the second overload, which then returns `undefined`). `isActive` is required, not null. Returns `seed` until this activation has seen a local day change, then the observed day, forward or back (a westward time-zone move follows the local date, as `useLocalDayChange` does, `use_local_day_change.hook.ts:15-18`). Mechanism: a module-level ticker shared by every mounted instance, started on the first subscriber and stopped on the last; it arms one timer to the next local midnight (rebuilt from the wall clock, the shape of `armTimer` in `src/utils/use_local_day_change.hook.ts:20-30`, notifying only when `AppState.currentState === 'active'`) and one `AppState` `change` listener that notifies and re-arms on `active` (`use_local_day_change.hook.ts:34-40`). Notify calls every listener in one synchronous loop, so all sheets on screen re-render in one batch and read one today (Rule: every preview on one open sheet reads the same today). Per instance, in a `useEffect` keyed on `[seed, isActive]`: inactive subscribes nothing; active takes `baseline = seed ?? toLocalDateString(new Date())`, subscribes a listener that, when the read day differs from `baseline`, moves `baseline` and sets the observed day in `useState<string | undefined>`, and runs that listener once right after subscribing, so a midnight between the render and the effect is caught (`check()` before `armTimer()`, `use_local_day_change.hook.ts:32-33`); the cleanup unsubscribes and clears the observed day. Return `observed ?? seed`. No clock read in render; `toLocalDateString` from `@/utils/format_date` (Rule: local date, never a UTC slice).
