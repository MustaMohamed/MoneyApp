base: 662bb98ac4bab1bcbd66ad30a887dc829fbba134 · verify: emulator · flags: data-loss migration · expected diff: ~100 lines outside tests, plus one ADR

## Steps
### 1. One definition of "edge whitespace" for schemas and repository
- File: `src/utils/strip_name_edges.ts` (new)
- Change: `export function stripNameEdges(name: string): string` returns `name.replace(/^[ \t\r\n]+|[ \t\r\n]+$/g, '')`. It is the only place the four characters are spelled in TypeScript; the migration in step 5 spells the same four in SQL. Not `String.prototype.trim`, which also strips NBSP and the other Unicode spaces the ticket keeps.

## Risks
- `add_edit_category_sheet.schema.ts` imports `zod/v4`, `Strings`, `CategoryType`, `Category` and `stripNameEdges`, none of which pulls a sheet or icon library, so the schema test does not depend on `@gorhom/bottom-sheet` or `@expo/vector-icons` loading under jest.
- Zod 4.5.4's `.overwrite` runs before `.min`; a Zod bump that reorders checks or stops refinements after a failed `min` changes which message the empty-name case shows, and the step 3 and 4 tests catch it.
- `getCategoryById` on update is one more read per save; the categories table is at most 59 rows, so no index concern.
- MA-054's branch (`feat/MA-054-whitespace-only-account-name`) carries only its plan today; it shares no file with this plan.
- The sheet's `catch` branch has no automated test and only its duplicate arm is in the emulator walk; the other arm is reachable only by forcing a repository throw.

## Self-assessment
Step 3 is the row I am least sure about. It bundles four changes across the sheet and a new schema file, the extraction with its new signature, the `catch`, the `saveError` clear and render; the extraction keeps the schema test off the sheet's transitive imports, so the test-first commit cannot turn on a module that fails to load. I also chose to read `type` from the sheet state on edit as well as on add, which is correct because `initialize` sets it from `editingCategory.type` before any validation runs, but a future change that stops seeding the state on edit would silently scope the check to the last tab instead of the category's type. The migration and repository steps are plain and mirror files already in the tree.
