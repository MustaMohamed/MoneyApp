## Risks
- `edit_account.md · fields at rest, large font`: on the tap that focuses a `Name` at rest, Android may report the tap's selection before the focus event; `INPUT_REST_SELECTION` would then move the caret to the start (`TextInput.js:200-216` sends any selection that differs from the last native one). Fallback inside step 4: set the start selection with the instance's `setSelection(0, 0)` on mount and on blur, and pass no `selection` prop.
- `edit_account.md · locked fields, large font`: if Uniwind lets the `className` colour outrank the transparent style entry, the input's own text draws under the overlay; the crop shows it as doubled text.
- `budget.md · summary balance beside its chip, label or action, large font`: a chip that takes most of the row shrinks the amount with no floor; Acceptance allows shrink.
- `budget.md · long word in a name, large font`: if `Telecommunicationsinfrastructure` fits the category detail's title line at 1.0, the seed needs a longer word.
- `edit_account.md · fields at rest, large font`: Android's `adjustsFontSizeToFit` in an absolutely positioned box fits against that box's width; a box that reports no width before layout would draw the amount at full size for a frame.

## Self-assessment
Step 4's `'start'` display for the `Name` is the least certain. It is the only fix that changes "which end of its value shows" without the overlay the 2026-10-14 Decision allows for money and locked fields alone, and it rests on Android scrolling a non-focused `EditText` to a selection set while it has no focus, and on React Native ordering the focus event before the tap's selection event. Neither is provable in Jest; the `fields at rest` walk on edit account is where it passes or falls back to the imperative `setSelection` the Risks line names.
