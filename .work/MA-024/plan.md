# MA-024 — List: per-type live caption on each row
base: 9b6912f4e3b024d6eb295c60745989a2f308c476 · verify: emulator · flags: money path · expected diff: ~180 lines

Contract in one line: `buildInfoRows` (`src/modules/dashboard/screens/dashboard/components/account_card.tsx:66`) stays the only place a caption figure is computed or formatted; the accounts module selects and joins its rows' text. Each row gains `kind` (which figure it is) and `amountText` (the card's `value` without its currency code), so the caption is byte-equal to the card. `amount: number` (ticket Context) is not used: the savings change row (`:134`, `signedStatValue`) and the base-equivalent row (`:152`, `formatOwnedAmountParts`) escalate a sub-unit EGP figure to 2dp and compose a zero-gated sign; reformatting the number with `formatCurrencyParts` would print `0` where the card prints `0.40` and would need the sign composed a second time in the list.

## Steps

### 2. Every info row says which figure it is and carries its bare amount text
- File: `src/modules/dashboard/screens/dashboard/components/account_card.tsx` (`InfoRow` `:58-63`, `buildInfoRows` `:66-202`, `signedStatValue` `:32`, `ownedAmountText` `:43`)
- Change: export `InfoRow` and a new `InfoRowKind = 'limit' | 'available' | 'dueDate' | 'monthSpend' | 'avgDay' | 'weekSpend' | 'monthStart' | 'change' | 'monthIn' | 'monthOut' | 'thisWeek' | 'inBase'`; add `kind: InfoRowKind` to every row and `amountText?: string`. Invariant: when `amountText` is set, `value === \`${amountText} ${code}\`` with `code` the account's currency for every row but `inBase`, whose code is the base currency; `amountText` is absent on the due-date row (`:97`) and on the Over Limit value (`:92`). Build it from `formatCurrencyParts` where `formatCurrencyAmount` is called today. `signedStatValue` (`:32`) and `ownedAmountText` (`:43`) keep returning strings: the headline balance at `:303` renders `ownedAmountText(...)` as a JSX child, so a changed return type fails `tsc` there. Instead, at the row literals: the `inBase` row (`:152`) calls `formatOwnedAmountParts` (already imported, `:26`) once, sets `amountText: parts.value` and `value: \`${parts.value} ${parts.code}\``; the savings `change` (`:134`) and `thisWeek` (`:197`) rows call `formatDisplayMagnitude(value, cur)` once, set `amountText: signAmountText(text, sign, printsAsZero)` and `value: signAmountText(\`${text} ${code}\`, sign, printsAsZero)` with the same zero-gated sign, which leaves `signedStatValue` with no caller and it is deleted. The card's JSX (`:236-373`) is untouched; the row order and every `value` string stay as they are (the existing test asserts them).
- Test: `__tests__/screens/dashboard/account_card.helpers.test.ts`, new describe: per type, the `kind` sequence in order (card `limit, available, dueDate`; cash `monthSpend, avgDay, weekSpend`; savings `monthStart, change`; USD bank `monthIn, monthOut[, inBase]`; EGP bank `monthIn, monthOut, thisWeek[, inBase]`); for every row with `amountText`, `value` equals `amountText` plus the code; savings change `amountText` is `+611` (USD `+610.50`) with no code; an overdrawn USD bank's `inBase` `amountText` is `−5,000`; the Over Limit and due-date rows have no `amountText`.

### 3. One caption per account type, selected from the card's rows
- File: `src/modules/accounts/screens/accounts/list/accounts_list.helpers.ts` (new)
- Change: `resolveAccountCaption({ account, rate, stats, isRateUsable, baseCurrency }): string`. Calls `buildInfoRows(account, rate, stats, isRateUsable, baseCurrency)`, indexes rows by `kind`, and reads `text(kind) = row.amountText ?? row.value` (Over Limit reaches the caption through `value`). By `account.type`: CreditCard → `accountCaptionCard(text('limit'), text('available'))`; PhysicalWallet → `accountCaptionCash(text('monthSpend'), text('weekSpend'))`; PhysicalSavings → `accountCaptionSavings(text('monthStart'), text('change'))`; SmartWallet with an `inBase` row → `accountCaptionSmartWallet(text('inBase'), CURRENCY_CONFIG[baseCurrency].code, formatRateDisplayMagnitude(rate).text)`; SmartWallet without one, and Bank → `accountCaptionBank(text('monthIn'), text('monthOut'))`. Invariants: `formatRateDisplayMagnitude` is only reached behind an `inBase` row, which `buildInfoRows` emits only when `isRateUsable` (finite, positive), so its `RangeError` cannot fire; the helper never reads `rate > 0`, never converts, never rounds, never calls `formatCurrencyParts`. A kind the branch did not emit (unreachable by construction) yields `ACCOUNT_TYPE_LABELS[account.type]`, the MA-023 line, in one comment. `stats` undefined is `buildInfoRows`'s own zero fallback (`:73`).
- Test: `__tests__/screens/accounts/accounts_list.helpers.test.ts` (new), fixtures via `makeTestAccount`, `PLACEHOLDER_RATE = 50`: EGP bank with `{month_in: 22300, month_out: 14950}` → `Month in 22,300 · out 14,950`; USD bank with cents → `Month in 1,250.75 · out 640.25`; `stats` undefined → `Month in 0 · out 0`; USD smart wallet, balance 1354.25, rate 48.85 usable, base EGP → `≈ 66,155 EGP at 48.85`; rate 50 usable → ends `at 50.00` (two-decimal floor, the canvas's `49.0` is not a format); EGP smart wallet, 1,000, base USD, rate 50 → `≈ 20.00 USD at 50.00`; smart wallet in the base currency, and one with `isRateUsable: false` at the placeholder rate → the bank caption and no throw; cash `{month_out: 4820, week_out: 1140}` → `Month spend 4,820 · week 1,140`; savings balance 25,000 with `{month_in: 6000, month_out: 1000}` → `Month start 20,000 · +5,000`, a negative month → `· −500` (U+2212), a flat month → `· 0` with no sign; card limit 40,000 balance 8,450 → `Limit 40,000 · available 31,550`, balance 45,000 → `Limit 40,000 · available Over Limit`; every non-smart-wallet caption `not.toContain('EGP')` and `not.toContain('USD')`.

- The canvas's `.cap` is 11px; MA-023 shipped the caption slot at `Type.caption` (12) and this plan keeps it, so a reviewer holding the row to the canvas pixel changes MA-023's geometry, not this ticket.
