## Self-assessment
Step 2 is the least sure. The host now learns `saving` and the error from a footer each session publishes in an effect, so on the first render after a session mounts, and in the window after a save starts, `footer` lags the form's own state. The plan covers the close path by reading the form states directly in `requestClose` and `isDismissable`, as the transaction host does, but a Save tapped before the session's register effect has run is dropped silently, and only the host hook test with a mocked registration asserts it.
