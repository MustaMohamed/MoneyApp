# MA-191 — A package.json commit that changes only npm scripts does not mark every emulator's APK for rebuild
base: 97669098a34fb0191fd40979d4da779e37d5785e · verify: none · flags: none · expected diff: ~80 lines

## Steps
### 1. One script decides whether a `package.json` change stays inside the scripts npm does not run on install
- File: `scripts/package_json_scripts_only.mjs` (new, ESM like `scripts/board_size.mjs`)
- Change: CLI `node scripts/package_json_scripts_only.mjs <old-rev> [<new-rev>]`. Git runs in the repo that holds the script, resolved from `import.meta.url` as the script directory's parent, the way `mqa.sh:19-20` resolves its root. `<old-rev>` (string, required) and `<new-rev>` (string, optional) each read `git show <rev>:package.json`; with `<new-rev>` omitted, the new side is the working-tree `package.json`. Exit 0 only when both sides read and `JSON.parse`, and their canonical forms are equal. Canonical form: when the top-level value is an object whose `scripts` is an object, `scripts` keeps only `preinstall`, `install`, `postinstall`, `prepublish`, `preprepare`, `prepare`, `postprepare`, `dependencies`, and is dropped when none remain; object keys sorted at every depth; array order kept; built as a string, so a `__proto__` key compares like any other key. Exit 1 on everything else: no `<old-rev>`, a side `git show` cannot read (no `package.json` at the rev, or a root commit's `^1`), no working-tree file, a side that does not parse, any other difference, any thrown error. Prints nothing to stdout.
- Test: `first` · `__tests__/scripts/package_json_scripts_only.test.ts` (new). The script is copied into a temp repo's `scripts/`, the way `mqa_needs_build.test.ts:60-65` copies `mqa.sh`. The base commit holds `dependencies`, a top-level `files` array of two entries and a `scripts` block with `lint` and `postinstall`. Working-tree form against `HEAD`: unchanged, `lint` edited, `lint` removed, a non-install script added, and re-indented with keys reordered at the top and nested all exit 0. Each of the eight install names added to a base without it, edited, and removed from a base with it (`it.each` over names and the three kinds), a `dependencies` version moved, the `files` entries swapped, `name` changed, unparsable text and the file deleted all exit 1. Rev form: `<root>^1 <root>` exits 1. `HEAD^1 HEAD` exits 0 on a `lint`-only commit, 0 on a commit that removes a `scripts` block holding only `lint`, and 1 on a commit that deletes `package.json`. No argument exits 1.

## Risks
- With `node` missing from PATH, every `package.json` change reads as reaching the APK, which is the verdict before this ticket. It never reads as a wrong `REUSE`.
- A push of a commit that touches `.github/workflows/` needs the SSH route, because the HTTPS token lacks `workflow` scope.
- No pull request runs the gate's skip branch before merge, because this PR changes none of the four paths. The hand run in Verification is the only proof until a later scripts-only PR.
- `base_native_commit` starts one node process for each scripts-only commit newer than the newest real native commit. At the base, 3 of the 15 native-surface commits since 2026-09-14 were `lint`-only (ticket Context).

## Self-assessment
Step 2 is the step I am least sure about. `base_native_commit` changes from an awk that exits on its first match to a candidate list filtered through `commit_native_files`. Under `set -euo pipefail`, a loop on the right of a pipe returns from a subshell and leaves `hit` empty. The verdict would then fall to the no-history `REUSE` line, which is a wrong `REUSE`, the one failure Rules line 1 forbids. The `lint`-only and merge cases in step 2's test catch it only when they assert the named sha, not just the `REUSE` prefix.
