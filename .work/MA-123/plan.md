The timer fires from the UI thread's frame callback and stops while the activity is paused (`node_modules/react-native/ReactAndroid/src/main/java/com/facebook/react/modules/core/JavaTimerManager.kt:72-76`, `:290-317`), so a busy UI thread or a pause carries a close's style past 2 s with no run in between, and it is dropped unsynced. React still renders the open style it was handed while the sheet stood open (`node_modules/react-native-reanimated/src/createAnimatedComponent/AnimatedComponent.tsx:538-546`), and the next React commit writes it back to the view, since the commit hook has no registry entry to lay over it (`node_modules/react-native-reanimated/Common/cpp/reanimated/Fabric/ReanimatedCommitHook.cpp:84-105`). gorhom's position stays closed (`node_modules/@gorhom/bottom-sheet/src/components/bottomSheet/BottomSheet.tsx:1029-1047`), so the host stays `closed` and the close button does nothing. The control run fits it: `no match` in the read straight after the two swipes, the title in the shot taken after that read, and no input between them (`~/.ship/MoneyApp/MA-123/findings/render/diag2/read.md`).
  - Why a wrapper. Its opacity and pointer events are React's own props on a plain `View`, which no animated style writes, so they hold whether or not that path is the one the device took.
- Test: `first` · `__tests__/components/ui/sheet_rest_props.test.ts` (new), on lifecycles built with `createSheetCloseLifecycle`, `syncSheetCloseLifecycle` and `settleSheetCloseLifecycle`: never opened hides; open shows; closing shows; settled at `-1` hides; reopened shows. `Sheet`'s wiring has no Jest case: no suite renders `Sheet`, and the host's suite mocks it (`__tests__/screens/transactions/transaction_form/transaction_form_host.test.tsx:49-78`). `reopen after two edge swipes` proves it: its forcing run draws the title under the source force and reads `no match` on head.
