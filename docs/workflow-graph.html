How a MoneyApp ticket moves

The board is the state. Skills move a ticket one column at a time, scripts write the board, and in an unattended run the human acts at four gates: the lock, the split, parked questions, and the merge; a typed run also asks on gaps, seams and disputed findings. 1. The board as a state machine

Every move, who makes it, and the one-way wall at Ready For Development. Forward moves run over the top; parks and returns run under the row into the Blocked trench.

2. Define: /epic, /boundaries, /tickets, /issue-review

Only /issue-review writes a Reviewed date, and only promote moves a leaf to Ready For Development. A parent is marked before its children and never pulled. An unattended review parks each ask as a question record instead of waiting.

3. /prep: Ready For Development to Planned

A cold planner plans from the ticket alone. Gaps are read against the parent, the frames, the ADRs and the code before anyone is asked. The size gate is counted twice more here and trims, never waives.

4. /ship: Planned to Awaiting Human

Five phases, one conductor that edits no code, fresh subagents that get paths and never the conversation. The run asks nothing: it rules by ticket text, frame, convention, then smallest change, and parks what it cannot rule.

5. /queue: unattended starts, and answering what parked

A column pass starts one app task per ticket under a lease and eight holds. The asks pass puts every open record to you, one per message, writes the answer into the ticket and moves it in the same step.
