## Overview

M1.5 builds the core daily interface: Dashboard, Account Detail + Edit, Add Account, Settings Main, and Settings Currency — plus the Adjust Balance sheet, Net Worth Breakdown sheet, Empty States, and Archive Confirmation dialog. Screens are designed and approved (Cairo Nights v7, Notion task pages U2–U26 + modals).

This spec covers navigation structure, file layout, state management, data flow, and navigation flows. UI design decisions are already locked in Notion.

## 3. File Anatomy Convention

Follows the existing per-screen pattern from onboarding:

| File | Responsibility |
|---|---|
| `index.tsx` | UI template only. No `useState`, no `useSharedValue`. Wires hook + anim outputs. |
| `<name>.hook.ts` | Logic, RHF/Zod schema, store reads, navigation. Uses `useZodForm`. |
| `<name>.store.ts` | Zustand for local non-form UI state only. Includes `reset()`. Omitted when not needed. |
| `<name>.anim.ts` | Reanimated shared values and animated styles. No business logic. |
| `components/` | Sub-components used only by this screen. Colocated here, not in global `components/`. |

`account_detail.store.ts` is needed — edit mode toggle is non-form local UI state.
`add_account` has no store — form state lives entirely in RHF (same as O4).
`settings/index.tsx` has no store — pure navigation.

## 4. State Management

### Existing stores — unchanged

| Store | Holds |
|---|---|
| `store/account.store.ts` | `accounts[]`, `loadAccounts()`, `addAccount(data)` |
| `store/onboarding.store.ts` | Onboarding step state |

### New store — `store/currency.store.ts`

```typescript
interface CurrencyState {
  rate: number                      // EGP per 1 USD, e.g. 50.25
  lastFetched: string | null        // ISO timestamp
  isManualOverride: boolean
  loadRate: () => Promise<void>     // reads persisted rate from app_settings
  fetchRate: () => Promise<void>    // calls ExchangeRate-API, persists result
  setManualRate: (rate: number) => Promise<void>
}

export function createCurrencyStore(repo: IAppSettingsRepository) {
  return create<CurrencyState>(...)
}

export const useCurrencyStore = createCurrencyStore(new AppSettingsRepository());
```

Repository receives the repo via factory (DI pattern), matching `createAccountStore`. Rate is persisted in the existing `app_settings` table under keys `usd_rate` and `usd_rate_fetched_at`. No new table or migration needed.

### No store needed for

- Dashboard net worth — computed inline in `dashboard.hook.ts` from accounts + rate
- Account Detail edit mode — in `account_detail.store.ts` (local, not global)
- Settings Main — pure navigation, no state
- Modals — local ephemeral state within their component

## 5. Data Loading Sequence

On app enter (`(app)/_layout.tsx` mount):

```
loadAccounts()   ← account.store — fetches all accounts from SQLite
loadRate()       ← currency.store — reads persisted rate from app_settings
```

Both fire concurrently on mount. Dashboard renders immediately with whatever is in the store. `fetchRate()` (ExchangeRate-API) runs in background — the USD rate badge updates when it resolves.

## 6. Net Worth Calculation

Computed in `dashboard.hook.ts`, not stored:

```
Assets      = Σ current_balance of non-CC accounts, converted to EGP
Liabilities = Σ current_balance of CC accounts, converted to EGP
Net Worth   = Assets − Liabilities
USD display = Net Worth ÷ currency.store.rate

USD account conversion: balance × currency.store.rate
```

## 7. Navigation Flows

| Trigger | From | To | Transition |
|---|---|---|---|
| O6 "Open My Dashboard" CTA | `(onboarding)/ready` | `/(app)/(tabs)/dashboard` | replace (no back) |

| "More" → Adjust Balance | Account Detail | Adjust Balance sheet | bottom sheet |
| "More" → Archive | Account Detail | Archive Confirmation dialog | modal overlay |
| Save (edit mode) | Account Detail | view mode in-place | store toggle, no nav |
| Save new account | Add Account | back to Dashboard | `router.back()` + store reload |
| Tap Settings gear | Dashboard header | `/settings` | stack push |
| Tap Currency row | Settings Main | `/settings/currency` | stack push |

## 8. Add Account — Code Reuse Strategy

`add_account.hook.ts` in `(app)/accounts/add_account/` extracts and reuses `createAddAccountSchema` from a shared location. The schema factory (Zod schema + validation rules) is moved to `utils/schemas/add_account.schema.ts` so both O4 and U4 import from there without cross-folder coupling.

UI context differs (stack nav header + Save button vs onboarding progress dots), but all business logic and validation is identical.
