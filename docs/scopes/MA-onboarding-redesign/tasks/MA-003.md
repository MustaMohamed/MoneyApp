# MA-003 — Cross Fan logo: launcher, adaptive, splash, in-app mark

## Summary

Replace the Expo placeholder artwork with the approved Cross Fan mark on the launcher icon, the Android adaptive icon and the splash screen, and deliver the compact in-app mark the onboarding header uses.

## Details

The app still ships the Expo placeholder icon. The approved mark is the Cross Fan — three fanned account cards behind the folded MoneyApp symbol — with the teal accent dot **on the card corner, not over the stem**. That nudge is settled at gate 1 (`scope.md`, decision 3) and is not re-opened: dot-over-stem is the anatomy of a lowercase "i", and at launcher size the old placement read as "Mi".

Source artwork is in this scope's `assets/` folder: a vector master for lossless generation and a verified 1024×1024 raster. Locked construction — card angles, the diagonal midnight gradient, the thin warm border, the compact scale that must not be enlarged to fill the tile, and the rule that no text is embedded in the launcher mark — is in `assets/locked-design-2026-07-23.md` § *MoneyApp logo system*, which is functional detail and still current.

**Four surfaces:**

- **Launcher icon** — the full tile.
- **Android adaptive icon** — foreground only, with **all geometry inside the adaptive safe region**. Android crops the foreground to a circle or squircle depending on the launcher, and the fanned cards reach toward the tile corners. This is the one that goes wrong silently, and it goes wrong differently on different launchers.
- **Splash screen** — the same mark on the existing midnight background.
- **The in-app mark** — a compact element the onboarding welcome header renders beside the wordmark. It may drop non-essential detail at that size but must preserve card order, angles, colours and the folded mark. **MA-004 consumes it**, so it ships here even though nothing renders it yet in this task.

### The native-config rule this task must not break

**This is the only task in the scope that touches native configuration.** It replaces the files the existing configuration already points at; it adds no plugin, no dependency and no native source. That distinction is the whole reason it is not a critical trigger, and the plan must keep it true.

Concretely, and non-negotiably:

- **Nothing in this task adds, removes or reorders a configuration plugin.** Only asset files change.
- **Do not run the dependency-fixing Expo command.** It is known to re-add a date-picker plugin whose own require throws, which takes down `expo config`, every local dev build, and the prebuild CI job with an opaque module-not-found error. `CLAUDE.md` § *Expo Dev Client* and `spec.md` § *Risks* both name it. If a plan step believes it needs that command, that is a signal the task has grown past replacing artwork — stop and escalate rather than running it.
- **Diff the app configuration after every Expo CLI invocation of any kind**, including a plain prebuild, and attach the diff to this file. An empty diff is the expected result and is worth recording as such.

**A rebuild is unavoidable.** New launcher artwork does not appear from a reload — the emulator run needs a fresh install, and stale-icon caching on Android will lie to you.

**Done when:** the launcher icon, adaptive icon and splash all render the Cross Fan on a freshly installed build; the adaptive foreground has been checked under a circular mask with nothing important clipped; the compact in-app mark exists and is covered by a test for its accessible name; the app-configuration diff is recorded in this file and shows only the intended change with no added or reordered plugin; and the full CI-parity chain including the Android prebuild step is green.

### Verified facts this plan rests on

Every number below was measured in this session against the files on disk, not recalled. `@plan-reviewer`: facts 1–5 are the load-bearing ones.

1. **`@expo/prebuild-config@57.0.10` maps the adaptive foreground 1:1 onto the 108 dp canvas.** `pbc/build/plugins/icons/withAndroidIcons.js:364` computes `iconSizePx = (isAdaptive ? ADAPTIVE_BASELINE_PIXEL_SIZE : LEGACY_BASELINE_PIXEL_SIZE) * scale` with `ADAPTIVE_BASELINE_PIXEL_SIZE = 108` (`:74`) and `resizeMode: 'cover'` (`:372`); `configureAdaptiveIconAsync` (`:206-224`) passes `backgroundColor: 'transparent'` and `isAdaptive: true`. A square 1024 source becomes a square `108 × scale` foreground with **no padding and no inset added by Expo**. Therefore the Android safe zone is measured on *our source PNG* at these fractions of its width:
   - **mask circle** (the 72 dp viewport a circular launcher crops to, inside the 108 dp canvas): radius `W/3` = **341.33 px**;
   - **safe zone** (Google's recommended 66 dp diameter for key elements): radius `W × 33/108` = **312.89 px**.
2. **The iOS icon is composited onto white with transparency removed.** `withIosIcons.js:183-203`: `size = 1024`, `resizeMode: 'cover'`, `removeTransparency: appearance !== 'dark'`, `backgroundColor: '#ffffff'`. **`assets/icon.png` must therefore be fully opaque.** The verified raster is: measured `min alpha = 255` across all 1 048 576 pixels.
3. **The Android legacy and round icons come from `icon`, not from the adaptive foreground.** `withAndroidIcons.js:154` (`legacyIcon = icon ?? foregroundImage`), `:163` `generateRoundIconAsync(projectRoot, legacyIcon, …)` whose `generateMultiLayerImageAsync` call passes `borderRadiusRatio: 0.5` at `:190`. So `ic_launcher_round.webp` is a **circular crop of the full tile at radius 512 px**. The tile's ink reaches 723 px into the corners (it is edge-to-edge opaque), but everything the corners hold is the `#050B11` outer canvas and the outermost sweep of the rounded-rect corner; the cards' own ink stops at 310.8 px. Nothing of the mark is lost. No action needed — recorded so it is not later mistaken for a defect.
4. **`imageWidth: 100` is the *correct* value for the Android 12 splash, and raising it toward Expo's default of 200 would clip.** Read from `expo-splash-screen@57.0.5/plugin/build/withAndroidSplashImages.js:100-124`: `size = imageWidth * multiplier`, `canvasSize = 288 * multiplier`, the image is `contain`-fit into `size` and composited at `(canvasSize - size)/2`. `withAndroidSplashStyles.js` sets `windowSplashScreenBackground`, `windowSplashScreenAnimatedIcon`, `postSplashScreenTheme` and `android:windowSplashScreenBehavior` — and **no `windowSplashScreenIconBackgroundColor`**, which puts us on Android's *icon-without-background* spec: a 288 dp asset whose visible area is a **192 dp circle**, radius 96 dp. Our image occupies a centred 100 dp square; its half-diagonal is `100 × √2 / 2 = 70.71 dp ≤ 96 dp`, with 25 dp to spare, **whatever the artwork is**. The clipping threshold is `imageWidth = 2 × 96 / √2 = 135.76 dp`. Expo's default 200 would put the corners at 141 dp and clip them. `__tests__/app_config_plugins.test.ts` pins `imageWidth ≤ 135`.
5. **`assets/splash.png` is a 1 × 1 fully transparent PNG, 68 bytes.** The splash has never rendered anything but `#0F1923`. This task gives it artwork for the first time; it is not a replacement.
6. **The master SVG's three card gradients are inert, and the cards render flat.** `moneyapp-logo-cross-fan.svg` declares `<linearGradient id="back-card" x1="28" y1="18" x2="100" y2="69">` etc. with **no `gradientUnits`**, so they default to `objectBoundingBox` while carrying user-space coordinates — x1 = 2800 % of the bbox. Every shape lies entirely before stop 0, so each card paints its stop-0 colour flat. Only `#background` (which *does* carry `gradientUnits="userSpaceOnUse"`) is a real gradient, so the locked "diagonal Cairo Nights gradient" on the **tile** is intact. **Do not fix this** — it is what gate 1 approved and what the verified raster shows. ### Step 5 — the PNG decoder

- [ ] `src/test_helpers/png.ts`. Node built-ins only. It deliberately **throws** on anything but 8-bit RGBA non-interlaced rather than guessing, so a future asset saved in a different format fails loudly instead of silently asserting on garbage:

```ts
import zlib from 'node:zlib';

export interface DecodedPng {
  width: number;
  height: number;
  /** RGBA, 4 bytes per pixel, row-major. */
  data: Buffer;
}

/**
 * Minimal PNG decoder for asset tests. Supports the only format this repo's
 * committed PNGs use: 8-bit, colour type 6 (RGBA), non-interlaced. Anything
 * else throws — a wrong-format asset must fail the suite, not slip through as
 * misread bytes. No dependency: `zlib` is a Node built-in.
 */
export function decodePng(buf: Buffer): DecodedPng {
  if (buf.readUInt32BE(0) !== 0x89504e47) throw new Error('not a PNG');
  let off = 8;
  let width = 0, height = 0, depth = 0, colorType = 0, interlace = 0;
  const idat: Buffer[] = [];
  while (off < buf.length) {
    const len = buf.readUInt32BE(off);
    const type = buf.toString('ascii', off + 4, off + 8);
    const data = buf.subarray(off + 8, off + 8 + len);
    if (type === 'IHDR') {
      width = data.readUInt32BE(0);
      height = data.readUInt32BE(4);
      depth = data[8];
      colorType = data[9];
      interlace = data[12];
    } else if (type === 'IDAT') idat.push(data);
    else if (type === 'IEND') break;
    off += 12 + len;
  }
  if (depth !== 8 || colorType !== 6 || interlace !== 0) {
    throw new Error(`unsupported PNG: depth=${depth} colorType=${colorType} interlace=${interlace}`);
  }
  const raw = zlib.inflateSync(Buffer.concat(idat));
  const bpp = 4;
  const stride = width * bpp;
  const out = Buffer.alloc(height * stride);
  let p = 0;
  for (let y = 0; y < height; y++) {
    const filter = raw[p++];
    const line = raw.subarray(p, p + stride);
    p += stride;
    const cur = out.subarray(y * stride, (y + 1) * stride);
    const prev = y ? out.subarray((y - 1) * stride, y * stride) : null;
    for (let x = 0; x < stride; x++) {
      const a = x >= bpp ? cur[x - bpp] : 0;
      const b = prev ? prev[x] : 0;
      const c = x >= bpp && prev ? prev[x - bpp] : 0;
      const v = line[x];
      let r: number;
      switch (filter) {
        case 0: r = v; break;
        case 1: r = v + a; break;
        case 2: r = v + b; break;
        case 3: r = v + ((a + b) >> 1); break;
        case 4: {
          const pp = a + b - c;
          const pa = Math.abs(pp - a), pb = Math.abs(pp - b), pc = Math.abs(pp - c);
          r = v + (pa <= pb && pa <= pc ? a : pb <= pc ? b : c);
          break;
        }
        default: throw new Error(`bad PNG filter ${filter}`);
      }
      cur[x] = r & 0xff;
    }
  }
  return { width, height, data: out };
}
```
