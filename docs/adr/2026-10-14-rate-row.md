# ADR: the add and edit sheet's rate is a Rate row that opens the rate editor

- **Date:** 2026-10-14
- **Status:** accepted
- **Ticket:** MA-170 (#697), under MA-096 (#552), epic #543
- **Applies to:** `src/modules/currency/store/currency.helpers.ts`; in `src/modules/transactions/screens/transactions/transaction_form/`, `transaction_form.helpers.ts`, `components/rate_row.tsx`, `components/rate_stale_line.tsx`, `components/form_picker_row.tsx`, `components/rate_editor_sheet.tsx`, `components/rate_editor_sheet.hook.ts`, `components/converted_amount_line.tsx`, `components/transaction_form.geometry.ts`, `transaction_form_body.tsx`, both form hooks and `edit_transaction.state.ts` in the same folder; `src/modules/transactions/components/exchange_rate_row.tsx`; `src/modules/transactions/utils/stored_rate_line.ts`
- **Supersedes in part:** `docs/adr/2026-10-13-converted-amount.md` §1 and §6

Frames D3, D5, D16 and D17 draw the rate as a card under the account strip. The user ruled on 2026-10-08 that the rate is a one-line row of the fields list, like Date, that opens an editor sheet. MA-168 (#695) moved the converted amount under the amount and MA-169 (#696) added the editor, opened from the card. This record covers the last of the three: the row, the editor's lines and Reset.

## 1. The Rate row is a fact row whose rounding never reaches the write

`RateRow(props: { ownerId: string; value: string; rateUpdatedAt: string | null })` mounts `FormPickerRow` with the id `exchange-rate-row`, the label `Rate`, a chevron, and the cell class the Date row takes, after To, Category and Budget and above Date, inside the `requiresRate` gate. Its value is `formatRateRowValue(value)`: `formatRateDisplayMagnitude(parsed).text` when `parseRateText` accepts the text, else the text unchanged, since the formatter throws on a rate that is not finite and positive. A press calls `openRateEditor(ownerId, value)` with the form's own text, so the editor opens on the unrounded rate and the save writes the rate as it is stored or as Done wrote it. The row has no mark for a custom rate and speaks `Rate, <rate>`, `FormPickerRow`'s default label.

`FormPickerRow` takes `labelCaption?: ReactElement`. Unset, the tree is as before, so the To, Category, Budget and Date rows do not change. Set, the label and the caption stack in one View with `flex: 1, minWidth: 0`, the label holds one line through the JS-scaled one-line props, and the value's box keeps its natural width until the row runs out and then shrinks (`flexGrow: 0, flexShrink: 1, flexBasis: 'auto'`), so the caption takes the ellipsis first and the rate only when it alone outgrows the row, and the row grows past `FACT_ROW_MIN_HEIGHT` through its `minHeight` floor. The Rate row sets it to `Rate may be stale` only while the stored rate is stale, the one state where it is taller than the Date row.

**Amended 2026-10-20, MA-197 (#759).** The row draws through `FactRow` (`src/components/ui/fact_row.tsx`) by way of `FormPickerRow`, and `FACT_ROW_MIN_HEIGHT` is gone: the floor is `resolveFactRowHeight(fontScale)` in `src/components/ui/fact_row.geometry.ts`, the height the Date row stands at. With `Rate may be stale` set, the row grows from that floor with `FACT_ROW_PADDING` above and below, 50.29 at font scale 1.0 and 85.33 at 2.0 on the 411 dp emulator.

## 2. One stale check, one stored-rate line

`isRateStale(rateUpdatedAt: string | null, nowMs: number): boolean` is true only when `nowMs` is strictly more than `RATE_STALE_THRESHOLD_DAYS` (30) days past the update. It is false for `null`, an unparseable time, exactly 30 days and a future time. The clock is an argument so the threshold is tested at 29, 30 and 31 days. It lives in `src/modules/currency/store/currency.helpers.ts`, and `formatStoredRateLine`, which formats copy, in `src/modules/transactions/utils/stored_rate_line.ts`, so the pay sheet's card does not load the form's helpers and the store's helpers hold no copy. The form body calls `isRateStale` once with `Date.now()` at render and hands the Rate row and the editor the same boolean; the pay sheet's card calls it itself. Both draw the line through `RateStaleLine`. `formatStoredRateLine(rateUpdatedAt)` is `Using stored rate · Last updated <en-US short date>`, or `Using stored rate` alone for `null`. The card's private copies of both are gone.

## 3. The editor's line reads the equality Done commits by

`resolveRateEditorSource({ draftText, storedRate, rateUpdatedAt })` returns `usesStoredRate` as `resolveRateCommit({ text: draftText, storedRate })?.override === false`, the rule Done commits by. While it is true the line is `formatStoredRateLine(rateUpdatedAt)`; otherwise it is `Custom rate · EGP per 1 USD`, so an empty or a bad draft reads custom. On the edit sheet the editor opens on the transaction's own rate, so a rate that differs from the stored one opens under the custom line with Reset showing.

## 4. Reset refills the stored rate and keeps the editor open

`useRateEditor(ownerId, value, onCommit, storedRateText)` returns `resetToStoredRate`, which sets the owner's draft to `storedRateText` through the store's `setDraft`. It clears a message as a keystroke does, keeps its identity per owner and writes nothing; only Done writes. `TransactionRateEditor` passes `formatStoredMoneyText(storedRate)`, the text the add hook seeds and `resolveRateCommit` writes. Reset sits under the converted amount, right-aligned, in `RATE_RESET_SLOT_STYLE`, a slot at `TouchSize.min` whether or not the link shows, so typing a rate moves nothing.

## 5. The editor's converted amount is `ConvertedAmountLine` at the draft

Under the field, in order: the source line, the stale line while stale, the message slot, `ConvertedAmountLine` with `exchangeRate` the draft, the id `rate-editor-converted-amount` and the text left-aligned, then the Reset slot. The line is the resolver's leg as `docs/adr/2026-10-13-converted-amount.md` §2 records it, so a bad or half-typed rate reads `≈ —`. `ConvertedAmountLine` takes optional `testID`, `textAlign` and `oneLine`, defaulting to the amount slot's id, centre and OS scaling. The editor passes the one-line props of its source line, so above scale 1 the converted amount is scaled in JS and its tail ellipsis stays inside its box; the line under the amount keeps OS scaling.

## 6. The override flag stays on add for the picks and leaves edit

Both form hooks expose `storedRate` and the body passes it to the editor. `toggleRateOverride` leaves both hooks. The add hook keeps `rateOverride` and `setRateOverride`: an account pick reseeds the stored rate only while no custom rate is set. The edit hook and `edit_transaction.state.ts` drop both, since nothing reads them once the card is gone. `applyRateCommit` takes `setRateOverride` as optional and calls it only when given; the edit hook passes none.

## 7. What leaves with the card

`components/transaction_exchange_rate_row.tsx` is removed. `ExchangeRateRow` returns to one props shape, `SharedProps & { onChange; error? }`, and loses its `onOpenEditor` branch, whose one caller was that wrapper. The commitments pay sheet passes the props it passed before and draws as before: `Exchange Rate`, `Custom rate`, `Reset to global` and its 2 dp preview.

## What this does not decide

The rate's place under the account strip as the frames draw it, a mark for a custom rate and a spoken stale state are not taken up. The stored rate and the currency settings screen are read and never written.
